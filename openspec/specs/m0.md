# M0: Rust-native OpenAI-compatible coding agent

Status: implementation candidate, not verified

## Requirements
- REQ-001: OpenAI-compatible Chat Completions endpoint, configurable base URL, model and API key.
- REQ-002: Bounded agent loop with tool call IDs and error feedback.
- REQ-003: Native read, list, grep, write and exact-match edit tools.
- REQ-004: Workspace boundary enforcement for reads and writes.
- REQ-005: Writes disabled by default.
- REQ-006: Cross-platform builds for Linux x86_64/aarch64 and Windows x86_64.
- REQ-007: Upstream Pi and OMP pinned references, compatibility test harness.

## Explicitly not delivered by this scaffold
Shell execution, JS extensions, native TUI,
OMP multi-provider coverage, verified binary builds, and complete security sandbox.

## M0.1 changes (implementation candidate, not compiled)
- REQ-008: Parse SSE Chat Completions and reconstruct indexed tool call fragments.
- REQ-009: Explicit opt-in JSON session persistence using `--session`.
- REQ-010: `--no-stream` fallback for gateways lacking SSE support.
- REQ-011: Treat truncated streams as errors, not successful final responses.

## Acceptance tests
1. Given a mock OpenAI-compatible server, the agent invokes read_file and returns final text.
2. Given a path escaping workspace, tool rejects it.
3. Without --allow-write, writes fail.
4. An edit with zero or multiple matches fails.
5. Invalid tool arguments become tool error results, not silent success.
6. CI validates formatting, lint and unit tests on each supported OS.

## Security follow-ups
- Implement atomic writes, symlink race mitigation, per-tool approval, output truncation,
  secret redaction, and process isolation before using on untrusted repositories.
- Current grep reads individual files up to 1 MiB; large workspaces need efficient streaming.

## M0.2 session storage requirements

- SQLite MUST support named sessions and persist messages transactionally.
- SQLite MUST use foreign keys, a busy timeout and WAL journaling.
- JSON message arrays MUST be importable/exportable via explicit CLI operations.
- The implementation MUST NOT claim native Pi JSONL compatibility.
- Session content MUST be documented as sensitive plaintext.
- SQLite roundtrip and independent-session isolation MUST have unit tests.
- File edits SHOULD be atomic and MUST reject ambiguous matches.
- Compilation, integration, and platform tests are required before M0.2 acceptance.

## M0.3 TDD contract — mandatory
- Every change MUST begin with a failing regression or acceptance test (red), then minimal implementation (green), then refactor.
- CI MUST enforce >=90% Rust line coverage using cargo-llvm-cov, counting all targets.
- CI MUST fail when coverage is below the threshold; no bypass or excluding difficult modules to raise the number.
- Security boundaries, SSE parser errors, SQLite isolation, tool approval and edit ambiguity MUST have negative tests.
- Mock-server integration tests MUST run without external LLM credentials.
- Each PR MUST include evidence of tests and measured coverage.
- 90% line coverage does not imply 90% behavioral correctness; mutation and branch coverage are future gates.
- This source package is NOT accepted until Rust CI and coverage gate pass.
