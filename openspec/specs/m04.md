# M0.4 — Reliability and TDD hardening

## Contract
- All production changes require a failing regression test first (RED), then implementation (GREEN), then refactor.
- CI must fail below 90% measured Rust line coverage; never report compliance without an actual `cargo llvm-cov` run.
- Tool paths must reject absolute inputs and `..` components; symlinks resolving outside workspace must be rejected.
- SSE responses must include `[DONE]` and a successful finish reason (`stop` or `tool_calls`); truncated completions fail closed.
- SSE input must have a bounded total size.
- SQLite session data must survive closing and reopening the database.

## Acceptance
- `cargo fmt --all -- --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test --all`
- `cargo llvm-cov --all-features --workspace --all-targets --fail-under-lines 90 --summary-only`
- Linux and Windows CI green.

## Explicit deferrals
- Race-resistant path confinement using OS directory handles.
- Live token rendering, cancellation, shell execution, QuickJS and native Pi JSONL import.
- Upstream OMP provider compatibility and complete Pi extension ABI.
