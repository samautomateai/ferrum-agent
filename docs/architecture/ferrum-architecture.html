Ferrum · Architecture blueprint · November 2026

One agent core.
Many ways to work.

A Rust-native coding agent that stays small at its center, supports rich workflows at its edges, and keeps authorization, execution and session state under one coherent architecture.

Rust nativeOpenAI-compatible modelsTUI + ACPA2A collaborationSkills + extensionsLocal-firstPermission-first

01 / What Ferrum will do

Develop

Code with context

Explore repositories, plan changes, edit files, run bounded tools, test and review. Preserve a coherent conversation and a verifiable record of actions.

Operate

Handle real engineering work

Investigate bugs, explain failures, navigate large codebases, carry out multi-step tasks and resume sessions without blindly repeating side effects.

Extend

Adopt ecosystems without copying them

Use declarative skills and installable extension packages; support Pi/OpenCode compatibility through adapters rather than embedding their entire runtimes in the core.

Non-goals: rewriting Pi wholesale, silently executing untrusted JavaScript, treating a worker process as a sandbox, or implementing a separate agent engine for each UI.

Design principle: TUI, ACP and A2A are adapters to the same core. The extension worker protocol is internal; it is not the same thing as ACP, MCP or A2A.

03 / What each ecosystem component means

Declarative

Skills

Versioned instruction bundles: SKILL.md, supporting references, prompts and optional templates. Loaded only when relevant; cannot grant permissions or execute code by themselves.

Packaging

Plugins

Installable distribution units with manifests, versions, dependencies and trust metadata. A plugin may contain skills, extensions, agents, prompts or configuration. Installation is not execution.

Executable

Extensions

Executable tool or hook providers, initially Boa-backed trusted JavaScript; future Pi/OpenCode adapters use isolated workers and a shared IPC contract. Permissions must be explicit.

Interface

TUI

Interactive terminal client for conversations, diff review, approvals, sessions, extension management and streamed tool events. A view onto the core, not a second agent.

Editor protocol

ACP

Agent Client Protocol adapter exposing sessions, prompts, updates, tool status and approval requests to compatible IDEs. Keep protocol-specific framing outside the core.

Agent federation

A2A

Agent2Agent adapter for task delegation and status exchange with other agents. Treat remote peers as untrusted principals with scoped identity, capability and data-sharing policy.

MCP fits differently: MCP is a tool/resource/prompt integration protocol. Ferrum can be an MCP client via a tool adapter; MCP is neither a UI nor a substitute for the core agent loop.

05 / Proposed plugin package and runtime contract

Example package manifest proposed

id: example.review-toolkit version: 1.0.0 ferrum_api: 1 components: skills: [skills/review/SKILL.md] extensions: [dist/review.js] permissions: requested: [workspace.read] compatibility: runtime: ferrum-boa

Actual schema must be specified, validated and versioned before implementation. Manifest requests never auto-grant capabilities.

Worker invocation contract proposed

ToolInvoke { protocol_version, request_id, session_id, extension_id, tool_name, arguments, deadline, granted_capabilities } ToolResult | ToolError | CancelAck

Worker startup, registration, cancellation, crash handling and shutdown require separate lifecycle messages. Never auto-retry a call that may have caused side effects.

06 / Security boundaries

Permission gate

Every built-in, extension and remote tool request is checked by one policy service. Unknown tools fail closed; write access is not inherited by extensions.

Process isolation ≠ sandbox

A worker can improve crash containment and deadlines, but does not inherently prevent filesystem, process or network access. True sandboxing needs OS-enforced controls.

Identity and audit

Attribute calls to user, session, client and extension. Record decisions and outcomes without leaking prompts, credentials or secrets into logs.
